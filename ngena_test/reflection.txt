NOTES/IMPORTANT CONCEPTS
///////////////////////////////////////////////////////
//- INTERNAL VS EXTERNAL LINKAGE
///////////////////////////////////////////////////////
EXTERNAL LINKAGE: means a variable or function can be
accessed across differrent translation units or files.
In this code g_taxrate and g_dailydiscount have external LINKAGE
They are defined in foodOrder.cpp and made accessible to tester_1.cpp
using the extern keyword in the header.

INTERNAL LINKAGE: This limits the scope of the variable or 
 function to the file where it is defined. while not explicitly
 forced with the static keyword on globals in this solution.

/////////////////////////////////////////////////////////
// STATIC VARIABLES
/////////////////////////////////////////////////////////
-> Static variable is a varibale that is allocated for
the lifetime of the program.
-> an example of Utility in this project is in the display()
function. static size_t numOrders = 0 is used
-> it is useful because it 'helps' the counter remember its
value between function calls without using a global variable.
This ensures the order numbering continues sequentially even
when moving from Day 1 to Day 2 or when displaying the recorded
delivery list.

/////////////////////////////////////////////////////////
// MEMBERS ADDED FOR MEMORY MANAGEMENT
/////////////////////////////////////////////////////////
The 'Rule of 3' is important for managing dynamic 
m_description. Adding the following members avoids memory leaks
-> Destructor [~FoodOrder]: To delete[] the dynamic memory
when an object goes out of scope.
-> Copy Constructor: does a 'deep copy' of the description
when an object is initialized from another.
-> Copy Assignment Operator (operator=): To clean up existing
memory and perform a deep copy when one object is assigned to
another.
-> A "Safe Empty State" logic: It's important to make sure that
m_description is initialized to nullptr in the constructor so that 
delete[] (on an empty object) doesn't crash.
