- What is meant by a program component of quadratic complexity?
---------------------------------------------------------------
A program component has quadratic complexity when its running
time grows with the square of the input size, written as O(n^2).
This often happens when one loop is nested inside another,
 causing the work to increase quickly as the input gets 
 larger.

---------------------------------------------------------------
- how do you use a smart pointer to move an object?
---------------------------------------------------------------
You can move ownership of an object by using std::move() 
with a smart pointer. After the move, the original smart 
pointer no longer owns the object, and the new smart 
pointer becomes its owner.

- what is an enumeration?
----------------------------------------------------------------
An enumeration (enum) is a user-defined type that contains
 a fixed set of named constants. It makes code easier to 
 read and reduces errors by giving meaningful names to
  values.

--------------------------------------------------------------------
- What is the difference between std::shared_ptr and std::unqiue_ptr
--------------------------------------------------------------------
A std::unique_ptr has only one owner and cannot be copied,
only moved. A std::shared_ptr allows multiple objects to
share ownership of the same resource and automatically
deletes it when the last owner is destroyed.

1. Why could we NOT use a unique_ptr in your Database class?
------------------------------------------------------------

-> We could not use a std::unique_ptr because getInstance()
returns the singleton object to multiple parts of the program,
and several variables may need to share ownership of the Same
Database object. A shared_ptr allows multiple shared references
to the same instance while ensuring the object is destroyed
automatically when the last reference goes out of scope

a signleton without using static members. how would that object be
managed?
--------------------------------------------------------------

-> Yes... Instead of using a static member inside the class, the
singleton object could be created and managed by another class or 
a dependency injection container that owns the object and passes it to
any code that needs it. In this design, the external manager is responsible
for ensuring that only one instance exists and for controlling its lifetime.

3. The class Database has a resource attribute (the database instance), yet
no copy/move operations were implemented. Is that a bug (justify your answer)?  
----------------------------------------------------------------------------
No. A singleton should never be copied or moved because that
could create additional instances of the class. Deleting the
copy and move operations is the correct design since only
one Database object is allowed to exist.

4. the class Database can be instantiated only once, yet in the output we see 
that the custom constructor is called twice (same for the destructor). Explain
------------------------------------------------------------------------------
The constructor is called twice because there are two
different template specializations: Database<std::string>
and Database<long long>. Each specialization is treated
as a separate class, so each one has its own singleton 
instance and its own constructor and destructor.
